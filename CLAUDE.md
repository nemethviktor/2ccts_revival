# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"2cc Trains In NML (Revival)": an OpenTTD NewGRF (trains) written in NML. Output is `2ccts_revival.grf`. See `docs/readme.md` for user-facing info (parameters, requirements, model/vehicle life rules).

## Build

The source is **mostly generated**. A Python step (`tools/`) reads an Excel master sheet and writes the `.pnml`/`.lng` files; then the C preprocessor and `nmlc` produce the GRF.

- Windows: `pybuild.bat` — runs `python -m tools.build`, then `gcc -E -x c -o 2ccts_revival.nml 2ccts_revival.pnml`, then `nmlc -c --quiet 2ccts_revival.nml -o 2ccts_revival.grf -t custom_tags.txt -n`, then the gap analysis (slow). `pybuild.bat y` skips the Python generation step and the gap analysis (build only).
- Linux/Debian: `pybuild_deb.sh [y]` — same flow (`y` = skip generation); needs `gcc`, `make`, `nml` (`tools/linux_requirements.txt`) and `tools/requirements.txt`; targets Python 3.12.
- Generate only: `python -m tools.build`. Gap analysis only: `python -m tools.generators.gap_analysis`.
- `Makefile` / `Makefile.config` is the stock NML framework configured for this repo, but the py scripts and `pybuild*` are the primary path. `Makefile.config` blanks `GENERATE_LNG` so `make` doesn't overwrite `custom_tags.txt` written by `tools/generators/version_info.py`.
- There is no test suite or linter.
- `*.nml`, `*.grf`, `custom_tags.txt` are gitignored build outputs.

## Architecture

- **Source of truth: `tools/data/vehicle_report.xlsx`** (one row per vehicle, plus vehicle-ID ranges, copyright text, notes). Do not open or read this file unless the user asks. Work from the generators in `tools/` instead. `tools/helpers/read_excel_file.py` loads it (`load_master_data`, `load_vehicle_id_ranges`); region flags are derived there from the REGION1..4 columns via `REGION_FLAG_TOKENS`.
- `tools/build.py` orchestrates the generators in `tools/generators/`: version info, badge table, languages, per-vehicle graphics pnml, master pnml, unified items, vehicle IDs, vehicle sort, vehicle summary markdown. Shared logic is in `tools/helpers/` (`role_rules.py` assigns vehicle roles, `paths.py` fixes folder-name casing so Windows-authored paths work on Linux).
- `2ccts_revival.pnml` is the master file (generated by `master_pnml.py`). It `#include`s `src/*.pnml` header files (regions, header, checks, templates, cargotable, vehicleID, railtypetable, badgetable, ...) in a required order, then per-vehicle pairs of `src/<Category>/<Name>_graphics.pnml` and `<Name>_item.pnml`. Categories are directories such as `Steam`, `Diesel`, `Electric`, `DMU`, `EMU`, `Coaches`, `Wagons`, `Maglev`.
- Because the vehicle pnml files, `vehicleID.pnml`, `vehiclesort.pnml`, `badgetable.pnml`, and the language files are generated, **hand edits to them are overwritten on the next `python -m tools.build`**. Change the generator or the Excel sheet instead. Files not touched by generators (e.g. `src/header.pnml`, `checks.pnml`, `templates.pnml`, `cargotable.pnml`) are hand-maintained; confirm in `tools/generators/` before editing anything.
- Translations: `lang/english.csv` (and other `*.csv`) are the editable sources; `lang/*.lng` are regenerated by `languages.py` and must not be edited. In translation strings use `[` `]` rather than `(` `)`, because suffix generation (e.g. "25kV AC") strips parentheses. See `lang/readme.md`.
- Docs `docs/vehicle_summary.md` and `docs/vehicle_gap_analysis.md` (plus images in `docs/gap_analysis`) are generated.
